# Supplier Risk AI Copilot — 한국어 개요

고객의 공급업체 온보딩 문제를 데이터 파이프라인과 검토 애플리케이션으로 연결하는 Deployment Strategist 포트폴리오 프로젝트입니다. AI가 평가 상태, 근거 인용문, 설명을 제안하면 검토자가 이를 확인하고 수락하거나 수정합니다. AI 원본 결과와 사람의 판단을 따로 저장합니다.

## 구현한 기능

- 가상의 구매자 보안 요구사항 5개와 평가 상태 4개: 충족, 부분 충족, 명시적 부재, 판단 불가.
- JSON 답변 평가 및 텍스트·스캔·혼합 PDF의 로컬 추출/OCR.
- 검토자가 답변과 출처 페이지를 확인한 후 LM Studio의 로컬 Open Weight AI model로 평가.
- 근거 인용문 검증, 수정 사유 기록, 변경 이력, 원본 결과 보존.
- 허용 목록에 지정한 Obsidian 노트의 선택적 활용. 개인 노트와 업로드 문서는 GitHub에 게시하지 않음.
- GitHub Pages의 공개 데모는 가상 데이터와 저장된 AI 결과를 사용하며 실제 추론 요청이나 PDF 업로드를 처리하지 않음.

## 결과와 한계

동결된 합성 평가 25개에서 로컬 모델의 상태 24개가 초안 정답과 일치했습니다. 이전 Gemini 실행은 23개, 키워드 기준선은 8개였습니다. 로컬 요청의 중앙 지연 시간은 약 26초였습니다. 작은 데이터셋이며 초안 정답이 독립적으로 검증되지 않았으므로 일반적인 모델 성능을 보장하는 결과는 아닙니다.

보안 담당자가 지정되었는지 불분명한 답변을 모델이 ‘명시적 부재’로 잘못 판단한 사례를 공개 데모에서 직접 수정할 수 있습니다. 인용문이 존재한다는 사실만으로 평가가 타당하거나 실제 보안 관행이 검증되는 것은 아닙니다.

영어·한국어 OCR 언어 파일은 준비했지만, 현재 PDF 검증은 영어 예제 중심입니다. 복잡한 표, 손글씨, 품질이 낮은 스캔 및 한국어 설문은 추가 평가가 필요합니다. 실제 고객 인터뷰, 운영 환경 배포, 규정 준수 인증은 주장하지 않습니다.

다음 단계는 보안 검토자와의 요구사항 검증, 수동 검토 대비 시간 및 수정률 측정, 더 큰 별도 평가 데이터셋 구축입니다.

## 고객 전략과 기술 구현

문서 추출·OCR, 확인된 답변 매핑, 구조화된 AI 평가, 사람의 수정 및 위험 요약을 연결합니다. Python/JavaScript 코드, LM Studio, 선택한 Obsidian 규칙과 프로젝트 메모리, 평가 및 테스트를 통해 기술 구현을 보여줍니다. 고객 파일럿 계획에는 이해관계자, 발견 질문, 교육 단계와 성과 측정 항목을 제시했으며 실제 고객 인터뷰나 사업 성과로 주장하지 않습니다.
